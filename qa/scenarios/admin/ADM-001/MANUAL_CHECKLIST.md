# ADM-001 — checklist R2 staging

Status awal `NOT_CONFIGURED`. Isi hasil setelah penguji menjalankan langkah pada domain staging dan mencatat SHA web/API, origin, alias bucket, tanggal, dan peran penguji. Gunakan proyek dan bucket khusus staging dengan data sintetis. Tetapkan area kurikulum uji yang tidak berisi paket Drill aktif dan gunakan akun Content Admin, Operations, serta dua siswa uji.

## Persiapan

1. DevOps memastikan `CONTENT_IMPORT_PREVIEW_ENABLED` dan `R2_MEDIA_UPLOADS_ENABLED` aktif pada API staging. Konfigurasi `R2_ACCOUNT_ID`, `R2_BUCKET`, `R2_MEDIA_PREFIX` dan kredensial API di secret store. Bucket private harus mengizinkan operasi pada `excel-uploads/` dan prefix media soal, termasuk objek sementara dan hasil verifikasi. Izin profile photo terpisah dari skenario ini.
2. Cocokkan origin HTTPS web dengan `CORS_ORIGINS` API dan [contoh aturan CORS bucket](../../../../docs/operations/r2-cors.example.json). Uji dari browser di domain tersebut agar preflight PUT ikut diperiksa. Periksa limit proxy untuk upload multipart dengan batas workbook 10 MiB dan overhead multipart.
3. Buka **Impor soal**, unduh template V5 dari staging, lalu isi sheet `PG` mengikuti [data uji](TEST_DATA.md). Siapkan dua salinan. Salinan lengkap berisi sepuluh soal. Salinan negatif memiliki satu gambar tanpa `alt_*` atau berisi file rusak untuk menguji penolakan. Gunakan judul `QA ONLY ADM-001 <tanggal/run>` dan pilih materi uji yang sudah `READY`. Sediakan persetujuan konten untuk paket uji sesuai proses tim.

## Langkah dan hasil yang diharapkan

| Pemeriksaan            | Langkah dan hasil                                                                                                                                                                                                                                                                                                                                                      |
| ---------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Arsip dan preview      | Unggah salinan lengkap dari browser. Preview menampilkan 10 soal, gambar pada sel yang tepat, dan alt text. Simpan progres, muat ulang, dan lanjutkan dari Riwayat unggahan. ID sesi dan edit yang sudah disimpan tetap sama.                                                                                                                                          |
| Validasi               | Unggah salinan negatif dan periksa pesan yang dapat ditindaklanjuti. Paket baru tidak terbentuk. Akun Operations tidak memperoleh akses unggah/review konten.                                                                                                                                                                                                          |
| Retry                  | Saat penyimpanan draft, blokir hanya request PUT ke bucket uji pada browser sendiri. Aplikasi menampilkan kegagalan. Periksa bahwa sesi tidak punya paket baru. Buka blokir dan ulangi dari sesi yang sama. Satu draft dengan 10 soal terbentuk dan dapat dibuka kembali. Ulangi setelah respons draft gagal diterima jika bisa disimulasikan secara lokal di browser. |
| Publikasi dan siswa    | Review dan terbitkan paket uji jika checklist/persetujuan lengkap. Akun siswa memulai Drill dari level uji. Gambar stem terbaca saat mengerjakan. Gambar pembahasan tersedia sesudah submit. Bukti aplikasi mencatat status gambar dan jumlah paket.                                                                                                                   |
| Akses dan masa berlaku | Siswa lain tidak bisa meminta link baru menggunakan attempt siswa pertama. Setelah link lama melewati masa berlakunya, buka ulang halaman atau gunakan mekanisme muat ulang media di aplikasi dan periksa bahwa link baru bekerja. Bukti cukup berupa status HTTP dan tampilan gambar. Jangan salin signed URL.                                                        |

Catat hasil per langkah sebagai `PASS`, `FAIL`, `BLOCKED`, atau `NOT_RUN`, beserta waktu, SHA dan ID sesi/paket/attempt. Gunakan screenshot dengan data sintetis dan tanpa URL bertanda tangan atau header autentikasi. Setelah pengujian, arsipkan paket uji sesuai prosedur konten dan catat ID-nya untuk tindak lanjut. Simpan histori attempt.
