# ADM-002 — checklist email Admin staging

Status awal `NOT_CONFIGURED`. Isi hasil setelah penguji menjalankan langkah. Catat SHA web/API, origin staging, alias proyek Auth, tanggal, dan peran penguji. Gunakan proyek Supabase staging terpisah, Super Admin uji, serta alamat baru di inbox yang dikuasai tim untuk setiap percobaan. Pisahkan browser Super Admin dan penerima.

## Persiapan

1. DevOps memastikan web dan API menunjuk proyek Auth staging yang sama. Siapkan SMTP dan pengirim terverifikasi, kebijakan password/masa berlaku token, template Invite dan Reset Password, dan allowlist redirect ke `/admin/auth/confirm` pada origin HTTPS yang benar. Recovery dari API dapat membawa `?type=recovery`. Ikuti [runbook Admin](../../../../docs/development/ADMIN_ACCOUNTS_RUNBOOK.md) untuk parameter `token_hash` serta `type=invite` atau `type=recovery`.
2. Set `ADMIN_AUTH_REDIRECT_ORIGIN` ke origin web staging dan simpan `SUPABASE_SECRET_KEY` hanya pada API. Aktifkan `ADMIN_ACCOUNT_INVITES_ENABLED` untuk penerimaan staging setelah konfigurasi dan isolasi diverifikasi. Periksa proxy dan observability agar query token, fragmen, password, dan email uji tidak ikut dikumpulkan sebagai bukti.

## Langkah dan hasil yang diharapkan

| Pemeriksaan              | Langkah dan hasil                                                                                                                                                                                                                                                                                                                                                                                      |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Undangan                 | Super Admin membuka Akun Admin dan mengundang alamat uji dengan assignment Operations. Catat status `INVITED` dan bukti inbox secara terpisah. Buka email pada browser penerima. Host tujuan cocok dengan staging. Parameter rahasia hilang setelah halaman memproses link. Tetapkan password, masuk, dan periksa status aktif serta menu sesuai Operations. Satu profil dan satu assignment tercatat. |
| Pemulihan                | Dari akun Admin aktif, jalankan Lupa password. Ulangi melalui tindakan recovery Super Admin pada alamat uji lain. Email benar-benar tiba dan membuka form recovery pada staging. Tetapkan password baru. Password lama ditolak saat login baru. Status dan assignment Admin tetap. Permintaan self-service ke alamat yang tidak terdaftar memberi pesan umum.                                          |
| Kedaluwarsa dan replay   | Buat undangan dan recovery khusus untuk kasus ini. Setelah masa berlaku yang dikonfirmasi DevOps, buka link yang belum dipakai dan pastikan form tidak muncul. Setelah link lain berhasil dipakai, buka ulang pada browser bersih. Form tidak muncul, password dan role tidak berubah. Gunakan link baru jika ingin mengulangi alur berhasil.                                                          |
| Hak akses dan pembatalan | Operations dan Content Admin ditolak saat membuka pengelolaan akun. Batalkan undangan yang masih tertunda lalu coba link yang sudah diterima. Akun tidak memperoleh akses Admin. Coba recovery pada akun yang sudah nonaktif dan tidak punya undangan aktif. Akun tetap nonaktif.                                                                                                                      |
| Pengiriman gagal         | Bila ingin menguji kegagalan SMTP nyata, gunakan transport atau inbox uji terisolasi yang disetujui DevOps. Periksa status/audit sebelum retry melalui operasi yang sama. Profil atau assignment ganda tidak boleh terbentuk. Email recovery bisa terkirim lebih dari sekali setelah hasil pengiriman ambigu.                                                                                          |

Catat status, waktu email tiba, jenis operasi, hasil login/penolakan, serta ID audit yang tersedia. Gunakan tangkapan layar yang menyembunyikan alamat, URL lengkap, dan token. Pada akhir pengujian, batalkan undangan uji yang tertunda dan nonaktifkan akun uji yang sudah selesai sesuai prosedur. Pertahankan Super Admin bootstrap dan audit.
