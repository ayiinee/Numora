# Admin assessment publisher — PRD v0.6

**PRD RULE:** Drill has ten items per level, one active MVP variant, unlimited retry, irreversible mastery unlock at >=80%, and latest-attempt stars (zero=0, 10–50=1, 51–99=2, 100=3). Tryout has thirty items, one attempt per package, the same package for its Monday–Sunday Jakarta batch, and a deadline at the earlier of duration and batch close. XP finalization is independent of IRT publication. Pretest authoring uses twenty items; its Student consumer is a separate backlog.

**ENGINEERING DECISION — user-approved implementation plan:** publish only reviewed content and a published, versioned policy with durable approval evidence. Policy selection is a read-only admin operation; product formulas have no Admin editor. Replacing a Drill package retires the prior selection atomically; existing attempts retain their package/content/policy pins. Approval records and used policy configurations cannot be rewritten. Legacy demo fixtures remain explicitly demo and are excluded from production policy selectors.

**OPEN:** Product must approve Tryout XP x10 versus x100, XP representation/rounding, and stars for partial scores outside the PRD ranges. Curriculum must approve PGK rubrics and Pretest distribution/blueprints. Data must approve respondent publication/mapping and scientific acceptance. Engineering can validate a versioned configuration, but cannot create evidence of those decisions. Production publication fails closed when the relevant approval or supported consumer is missing. Preview remains unscored.

Acceptance must cover direct HTTP authorization, immutable approval/content pins, package replacement races, single-package retry, score zero, latest versus best statistics, duplicate finalization/XP, batch-close race, and no keys/explanations in active responses. Local fixture tests are separate from Cloud, Curriculum/Data and independent QA acceptance.

## Versioned engineering boundaries

**ENGINEERING DECISION - integration with PR #77:** the selector reuses the canonical published `DRILL_PRD_V06` and `TRYOUT_PRD_V06` v1 policies only when their complete immutable configuration equals the canonical migration. Approval proof links the Product decision documents; approver UUID/time are nullable for an external approval and are never fabricated. These PG-only policies do not approve PGK rubrics. Rich-content scoring versions require stored approver/time/reference. Product constraints remain fixed: PG/MCMA/Category weights 2/3/3, Tryout x10 and ceil once, Drill equivalent-correct x10 plus speed bonus and nearest integer once. A configuration contradicting these rules is rejected even if labelled approved. Score/item precision and low partial stars still require an approved handoff.

**PROPOSED PGK boundary:** `NUMORA_PGK_LOOKUP_V1` uses exhaustive `(correct, wrong, category)` entries in an explicitly approved SEALED rubric. MCMA counts selected correct/incorrect options; Category counts matched/mismatched answered statements. Supported lookup coverage must be single-valued, bounded, complete and identify full correctness. Weighted points, equivalent credit, integer ordinal category, omission state and full correctness are stored separately. This contract is an engineering proposal requiring Curriculum/Data approval, not the scoring draft's assumed wrong-option or B=4 rule. Pinned approved RETIRED rubrics remain usable by historical/in-flight attempts.

**ENGINEERING DECISION:** editorial publication/review stores a manifest digest distinct from scientific `frozen_at`. Database guards prevent changing items, policies, duration or batch times after editorial pinning. Scientific generated packages retain their existing compute quality and distribution gates; no editorial operation manufactures a scientific PASS. Legacy unpinned demo/seed fixtures retain the original used/frozen guards. New Drill replacement publication serializes by level and retires the prior package atomically. Tryout publication serializes by Jakarta batch and creates durable cutoff/due timestamps. Existing IRT prepare prerequisites remain explicit dependencies, including scientific frozen package/release policy pins.

Student active DTOs project stem/options/categories/saved answer only. `answer` supports PG, MCMA and Category; legacy PG `optionId` remains accepted, with ambiguous dual payloads rejected. Media URLs are temporary capabilities issued only for the owner's pinned attempt item. WORK cannot request explanation media; REVIEW requires finalization and the pinned legacy/new Drill retention or IRT publication gate. Keys and explanations are returned together only by the gated result reader. Browser Auth does not read business data from Supabase.

Pretest `/api/v1/admin/content/pretest-packages` supports drafts, edits, review, family version/replay, archive, detail and paginated lists. Review requires 20 distinct, ready, same-chapter items. A supported SEALED blueprint also needs explicit durable approval evidence and a matching chapter. Production publish always reports the separate Student-consumer blocker; there is no override or force publish. No Pretest score or XP is calculated by these admin operations.

Migrations 0032-0036 extend numeric reward provenance and durable approval evidence, immutable editorial pins, and legacy fixture compatibility. They were applied only to the localhost synthetic test cluster. No approved production policy/rubric/blueprint was created and no Cloud schema was changed.
