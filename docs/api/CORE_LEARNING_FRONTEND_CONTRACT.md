# Core Learning Student API — implementation contract

**Status: implementation awaiting FE/BE/QA review, 1 October 2026.** Drill, assessment history, and the generic PG Tryout lifecycle below are implemented in NestJS and generated in `packages/contracts/openapi/openapi.json`; frontend types are generated from that contract. Official Tryout publication remains **OPEN-05** and is rejected by the Admin API. The Tryout integration test uses explicitly labeled demo fixtures. This document does not approve unresolved product rules. See [backend implementation status](../development/CORE_LEARNING_BACKEND_STATUS.md) for verification and remaining gates.

All endpoints use `/api/v1`, Supabase access token Bearer authentication, UUID identifiers, camelCase JSON, ISO-8601 UTC timestamps, and `application/problem+json` errors. NestJS authorizes the current Student, each attempt, and level access. No endpoint accepts a client-computed score, elapsed time, XP, or unlock state.

| Operation                                                             | Expected request               | Minimum response                                                                                                                      |
| --------------------------------------------------------------------- | ------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------- |
| `GET /chapters`                                                       | —                              | `{ chapters: { id, title, order }[] }`                                                                                                |
| `GET /chapters/{chapterId}`                                           | —                              | `{ chapter, subchapters: { id, chapterId, title, order }[] }`                                                                         |
| `GET /subchapters/{subchapterId}`                                     | —                              | `{ subchapter, levels: { id, title, order, status, latestScore, bestScore }[] }`; status: `locked`, `open`, `inProgress`, `completed` |
| `GET /students/me/progress`                                           | —                              | `{ completedLevels, totalLevels, latestScore }`                                                                                       |
| `POST /assessments/drill/attempts`                                    | `{ levelId }`                  | Current/new attempt; repeated start for an active level returns the same in-progress attempt                                          |
| `GET /assessment-attempts/{attemptId}`                                | —                              | Attempt with `id`, `levelId`, `levelTitle`, `status`, `startedAt`, `isDemo`, and ordered `questions`                                  |
| `PATCH /assessment-attempts/{attemptId}/answers/{questionInstanceId}` | `{ optionId: string \| null }` | `{ questionInstanceId, selectedOptionId }`; `null` clears the answer                                                                  |
| `POST /assessment-attempts/{attemptId}/submit`                        | —                              | Persisted result; repeated submit returns the same result                                                                             |
| `GET /assessment-attempts/{attemptId}/result`                         | —                              | Persisted result with score, raw points, answer review, explanation, mastery, stars, and unlock effect                                |

Before submit, each question has `{ questionInstanceId, stem, options: { id, text }[], selectedOptionId }`. It must **not** include a correct option, answer key, or explanation. The demo package has 10 ordered `SINGLE_CHOICE` questions with A–D options; simple inline math uses `$...$`. The result adds `score`, `rawPoints`, `correctCount`, `questionCount`, `mastered`, `stars` (legacy nullable output; all final thresholds now DRL-OPEN-03), `unlockedLevelId` (nullable), and `explanationState` (`available` or `expired`). Reviewed questions include `correctOptionId` and `explanation` only while explanation is available. **Legacy implementation:** Backend enforces a 90-day access limit without deleting the historic score; Drill v1.2 makes retention DRL-OPEN-07, so this is a gap requiring policy review.

Frontend saves each selection before allowing final submission. A failed save remains visible and retryable. Server owns the assessment lifecycle, finalization, 80% unlock rule, historical question/scoring context, and idempotency. The UI invalidates cached progress and level status after submit, then fetches the persisted result. Student onboarding and teacher monitoring have separate contracts and owners.

**Implementation details for review:** `optionId: null` clears an answer; active attempts return no answer key or explanation. Error codes include `LEVEL_LOCKED`, `ATTEMPT_NOT_FOUND`, `ATTEMPT_COMPLETED`, `RESULT_PENDING`, `QUESTION_NOT_FOUND`, `OPTION_INVALID`, and `DRILL_PACKAGE_UNAVAILABLE`. The first demo fixture has two 10-question equivalent packages for retry. Submit persists score, progress, and outbox atomically; XP is deferred pending **OPEN-11**. A result below 80 returns `recommendations`, containing zero to three READY videos mapped to the subchapter. PostgreSQL integration tests cover concurrent start/submit, retry, ownership, answer clearing/resume, historical versions, and progress references. Staging browser E2E and Curriculum review remain release gates.

## TryOut and Penilaian — generic lifecycle implemented

The web exposes separate Practice & Drill, TryOut, and Penilaian areas backed by these endpoints. TryOut remains outside the first school trial; question count **35** and PG/PGK MCMA/PGK Category are now FINAL in TryOut v1.1. Duration, scale, domain composition and PGK scoring rubrics remain **OPEN-05/OPEN-04**. The PG-only contract below is a legacy implementation gap. The frontend renders package values supplied by Backend. Only SINGLE_CHOICE scoring is supported. The package's pinned maximum points determine the fixture's normalized PG score; this does not resolve the official IRT model or final Tryout score policy.

| Operation                                                         | Expected request               | Minimum response                                                                                                                                                                                                    |
| ----------------------------------------------------------------- | ------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GET /tryout/packages/current`                                    | —                              | `{ state: "unavailable" }` when no package exists; otherwise `{ id, title, releaseAt, state, eligible, attemptId, questionCount, durationSeconds }` with state `open`, `inProgress`, `waitingIrt`, or `resultReady` |
| `POST /tryout/attempts`                                           | `{ packageId }`                | Existing/new attempt for the current package; duplicate start does not consume another attempt                                                                                                                      |
| `GET /tryout/attempts/{attemptId}`                                | —                              | `{ id, packageId, packageTitle, status, deadlineAt, questions }`; answer key and explanations are absent                                                                                                            |
| `PATCH /tryout/attempts/{attemptId}/answers/{questionInstanceId}` | `{ optionId: string \| null }` | Acknowledged saved answer; `null` clears it                                                                                                                                                                         |
| `POST /tryout/attempts/{attemptId}/submit`                        | —                              | `{ state: "waitingIrt" }`; duplicate submit remains idempotent                                                                                                                                                      |
| `GET /tryout/attempts/{attemptId}/result`                         | —                              | Score and explanations **only after** IRT release; before that, `application/problem+json` with code `TRYOUT_RESULT_PENDING` and no score/key                                                                       |
| `GET /students/me/assessment-results?cursor={cursor}`             | —                              | `{ records: { attemptId, activity, title, submittedAt, resultState, score }[], nextCursor }`; `score` is `null` while a TryOut waits for IRT                                                                        |

Backend determines Student affiliation, weekly package selection at Monday 00:00 WIB, one attempt per package, any deadline, final score, and IRT release. The browser presents those states without locally granting eligibility or revealing a result early. Penilaian is the Student-facing result/history view, not a scoring engine. Historical Drill results stay available even when Drill explanation access expires after 90 days, subject to final retention review under DRL-OPEN-07.

**PRD RULE — TryOut v1.1:** all Students including Mandiri have free MVP access; no class/payment prerequisite. **ENGINEERING DECISION — JOB-07 tahap pertama, 2 October 2026:** current/start now accept both affiliations. `eligible` describes permission to start a **new** attempt for the current available package: true without an attempt, false with an existing attempt. It is omitted in `{ state: "unavailable" }`; that state means no running package, not denied feature access. Existing attempts use `inProgress`, `waitingIrt`, or `resultReady`, with `attemptId` for resume/result navigation. Start snapshots the active class or null for Mandiri and never rewrites that snapshot after joining a class. No endpoint or migration is added; DTO descriptions, OpenAPI and generated types are synchronized.

**Implemented verification:** saved answers after `deadlineAt` are rejected; submit grades only persisted answers and is idempotent. A successful, explicitly released IRT batch must cover every pinned package question version with `sampleSize >= 30` and `dataStatus: SUFFICIENT` before result/history returns a score. This is the existing release gate, pending reconciliation with the latest low-response policy; access changes do not approve it as final. The history endpoint uses a UUID cursor, returns at most 20 records, and includes completed Pretest records when that lifecycle is implemented. Anonymous/invalid sessions return 401, Teacher/Admin or disabled accounts 403, foreign attempts 404, and unavailable/future/expired packages reject start with 409 `TRYOUT_PACKAGE_UNAVAILABLE`.

**OPEN / remaining work:** automatic finalization without another browser request, daily IRT model execution, batch schedule/model/failure policy (**OPEN-12/OPEN-18**), Pretest package/placement (**OPEN-01–03**, **DRL-OPEN-04**), and XP (**OPEN-11**) are not complete. The ≤3×24h release requirement is already FINAL. Official Tryout publishing stays unavailable until the remaining approved product configuration and release tests are supplied.

## JOB-12 history additions - 2 October 2026

**ENGINEERING DECISION - implementation requested by Aini, awaiting review:** history reuses `GET /students/me/assessment-results`. Optional UUID query `levelId` filters by the level pinned at attempt start; keep the same filter when supplying `cursor`. Omitting both queries returns the first page. The response remains `{ records, nextCursor }`, at most 20 records sorted by `finishedAt DESC, attemptId DESC`. PostgreSQL timestamp precision is retained at the cursor boundary, including microseconds. A foreign, missing, cancelled, unfinished, non-history, or wrong-filter cursor returns 404 `CURSOR_NOT_FOUND`; malformed UUID queries return 400. A filter without matching history returns an empty page.

Records add optional nullable `chapterId`, `chapterTitle`, `subchapterId`, `subchapterTitle`, `levelId`, and `levelTitle`. Chapter/level IDs come from attempt snapshots; taxonomy labels resolve from current preserved taxonomy and are not immutable historical labels. Archived content/package/level does not hide completed history or recalculate stored scores. All valid retries remain separate; latest/best level scores still come from the existing level/progress contract, with best score monotonic.

Optional `xpState` / `starsState` are `pending` or `notApplicable`. Numeric XP posting/formula remains JOB-11/OPEN-11; Drill star thresholds remain DRL-OPEN-03. Pretest marks both not applicable; TryOut marks stars not applicable. These fields do not mean zero reward or grant a new policy. Existing stored scoring facts are preserved and are not rewritten by this read endpoint.

The shared `ActivityRow` displays taxonomy/level context and pending reward text. Waiting TryOut records hide score and have no result link; ready Drill/TryOut records link to their existing result routes. Pretest remains a non-link row until its lifecycle/result route exists. The history view retains earlier pages on next-page failure and retries with the same cursor. OpenAPI/generated types remain authoritative; additions are optional for compatibility with existing consumers.

**OPEN:** numeric rewards, retention limits, Pretest lifecycle and final TryOut release policy are not resolved by JOB-12. The existing released-IRT gate is reused without alteration. History persistence is independent of the legacy Drill explanation expiry; no new retention/deletion policy is introduced.

## JOB-09 automatic finalization - 3 October 2026

**ENGINEERING DECISION:** no endpoint or response shape changes. Manual submit, authenticated resume/current recovery, and scheduled recovery use one PostgreSQL transaction and attempt row lock. An expired owned TryOut is finalized on resume; questions disappear and the existing waiting/released states apply. Both concurrent manual and automatic submission return the existing waiting response without duplicating finalization or its legacy outbox event. The existing internal PG score is not the approved IRT-weighted result.

The authoritative expiry check uses PostgreSQL wall time after the row lock. Save after `deadlineAt` returns 409 `TRYOUT_DEADLINE_PASSED` while active, or the existing completed error after finalization. Saved answers and their save timestamps, startedAt, deadlineAt, scoring/content pins and class snapshot remain immutable during finalization. Unanswered items receive blank answers for grading. FinishedAt records actual finalization time; it does not pretend recovery ran at the deadline.

**OPEN:** official duration, package-close/attempt-deadline relationship, PGK rubric and batch/release policy. Recovery only consumes persisted deadlines and never expires Drill. The existing UI countdown uses serverTime/deadlineAt and submits at zero without confirmation; browser availability is not required for scheduled recovery. Result, key and explanation remain behind the existing release gate.
